## 〇、Big-O 前备知识（速览）

- **忽略常数与低阶项**：`3n + 100` 和 `2n` 都记为 `O(n)`；`n² + n` 记为 `O(n²)`
- **O(log n) 直觉**：规模每翻一倍，操作只多一步（二分、平衡树）
- **摊还分析**：`list.append` 偶尔触发扩容，平均每次仍是 O(1)
- **最坏 vs 平均**：哈希表平均 O(1)、最坏 O(n)（冲突）；快速排序平均 O(n log n)、最坏 O(n²)
- **递归复杂度**：递归次数 × 每次递归的代价（可对照 [[02-Wiki/专题总结/05-二叉树]] 的 O(h) 递归栈）

## 二、排序算法复杂度

| 算法 | 平均时间 | 最坏时间 | 最好时间 | 空间 | 稳定 |
|------|----------|----------|----------|------|------|
| 冒泡排序 | O(n²) | O(n²) | O(n) | O(1) | ✅ |
| 选择排序 | O(n²) | O(n²) | O(n²) | O(1) | ❌ |
| 插入排序 | O(n²) | O(n²) | O(n) | O(1) | ✅ |
| **快速排序** | **O(n log n)** | O(n²) | O(n log n) | O(log n) | ❌ |
| **归并排序** | **O(n log n)** | O(n log n) | O(n log n) | O(n) | ✅ |
| **堆排序** | **O(n log n)** | O(n log n) | O(n log n) | O(1) | ❌ |

### 面试中的经验法则

| 数据范围 | 算法方向 |
|----------|----------|
| n ≤ 100 | O(n³) 没问题，考虑 DP |
| n ≤ 1000 | O(n²) 可接受 |
| n ≤ 10⁵ | O(n log n) 是安全的，考虑排序/二分 |
| n ≤ 10⁶ | O(n) 线性算法 |
| n > 10⁶ | O(n log n) 也要谨慎 |

## 六、常见复杂度增长对比

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)

n=10:    1 < 3 < 10 < 33 < 100 < 1024 < 3.6M
n=100:   1 < 7 < 100 < 664 < 10K < 1.3e30 < 9.3e157
n=1000:  1 < 10 < 1000 < 9966 < 1M < 很恐怖
n=10⁵:   1 < 17 < 100K < 1.7M < 10^10 < 不可能
```

> **面试要点：** 能写出 O(n log n) 的算法通常就算合格，O(n²) 需要能分析出来并尝试优化。
